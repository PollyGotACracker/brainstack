# 사건 문서 기록 규칙

## 목적

- 반복되는 비용 낭비를 줄인다.
- 더 효율적인 워크플로우로 시스템을 개선한다.

## 작성 대상

- 규칙·요구사항의 의도 해석 실패를 기록한다.
- 규칙·요구사항을 누락한 검수를 기록한다.
- 응답 또는 작업 결과의 규칙·요구사항 충족 실패를 기록한다.
- 응답 또는 작업 결과에 대한 사용자의 부정적 피드백을 기록한다.

## 작성 승인

- 에이전트 오류를 확인한 시점에 문서를 작성·수정한다.
  작성·수정 계획에 대한 사용자 승인 후 실행한다.
  결과와 함께 변경 위치를 보고한다.

## 상태 값

### 조치 상태

- `미착수`는 조치 시작 전 상태이다.
- `진행`은 조치 중이거나 남은 조치가 있는 상태이다.
- `완료`는 필요한 조치가 모두 끝난 상태이다.

### 시스템 적용 상태

- `미적용`은 예방 행동의 시스템 반영이 아직 이뤄지지 않은 것으로 확인된 상태이다.
- `부분적용`은 필요한 적용 범위 중 일부가 반영되고 남은 범위가 있는 상태이다.
- `적용`은 적용 범위가 실제 지침·코드·설정에 반영된 근거가 있는 상태이다.

### 구분 원칙

- 문서 작성 완료, 조치 완료, 시스템 반영, 재발 방지 효과를 개별로 구분한다.

## 절별 내용

### 적용 관련 절

- `시스템 적용`
  - 예방 행동의 반영 상태, 적용 대상, 확인 근거, 남은 적용, 재발 방지 효과
  - 적용 상태에 실제 지침·코드·설정 위치와 확인 근거를 병기한다.
- `시스템 적용 갱신`
  - 적용 이력이 생길 때마다 갱신 시점별 항목
  - 새 항목은 절 맨 위에 추가한다.

### 사건 관련 절

- `사건 경과`
  - 당시 작업·요청 요약, 기대 동작·규칙, 실제 결과·영향, 수행 절차, 관련 문서
- `원인과 처리`
  - 확인된 원인, 조치 사항, 미조치 사항
- `예방 행동`
  - 문제 발생 조건, 예방 행동, 준수 기준
  - 조건이 여럿이면 조건·행동·준수 기준 묶음을 목록 항목으로 반복한다.

## 표기

### 기록 원칙

- 이 양식으로 생성·수정하는 문서의 모든 서술 문구는 의미와 적용 조건을 보존한 평서문으로 작성한다.
- 양식 필드에 기록할 내용이 없으면 `기록 없음`을 표기한다.
- 실제 사건과 확인한 내용만 기재하고 원인·효과의 미확인은 그대로 표시한다.
- 근거가 부족하면 미확인 내용과 필요한 확인을 명시한다.
  실제 반영과 효과는 근거 확인 후 확정한다.
- 문서 내 에이전트 지칭은 역할로만 작성한다.

### 식별자 표기

- 사건 ID는 `YYYYMMDD-HHMM-<영문-slug>` 형식이다.
  날짜·시각은 파일 생성 시각(KST)으로 표기한다.
  slug는 사건의 고유 제목으로 작성한다.
- 파일명은 `<사건-id>.md`이다.
- 대상은 경로 대신 이름·작업 ID·절 제목으로 표기한다.
- 위치는 절 제목·기호로 표기한다.
  읽기 범위 제한용 행 범위와 기준 커밋을 병기한다.
  기준 커밋 이후 변경된 파일은 절 제목·기호로 위치를 재확인한다.
- 사용하는 시각은 KST로, 아래 커맨드를 사용한다.

```bash
TZ=KST-9 date '+%Y%m%d-%H%M'
```

## 작성 절차

### 작성 단계

1. 실패 기록 대상 사건을 기존 기록과 대조한다.
   이번 발생·재발 사실과 실제 조치·남은 한계를 정리한다.
   정리한 내용을 양식 필드에 대응시킨다.
2. 양식 필드의 누락 정보 중 현재 작업에 해당하는 미확인 내용만 사용자에게 확인한다.
3. 새 사건은 아래 템플릿을 기반으로 사건 문서 경로에 작성한다.
4. 추가 기록을 실제 파일에서 확인하고 기록 위치와 미완료 조치를 보고한다.

### 템플릿

```markdown
# <사건명>

- 사건 ID: <사건-id>
- 관련 작업 ID: <관련 작업 ID>
- 발생·확인 시점: <YYYY-MM-DD HH:MM>
- 관련 담당: <사건을 발생시킨 담당>
- 조치 상태: <미착수 | 진행 | 완료>

## 시스템 적용

- 상태: <미적용 | 부분적용 | 적용>
- 적용 대상:
  - <실제 지침·코드·설정 이름과 절>
- 확인 근거:
  - <확인한 반영 사실과 대상 이름·실행 근거>
- 남은 적용:
  - <남은 범위 | 없음>
- 재발 방지 효과:
  - <확인 결과와 근거 | 미확인>

## 시스템 적용 갱신

- <YYYY-MM-DD HH:MM>
  - 상태: <미적용 | 부분적용 | 적용>
  - 적용 대상:
    - <실제 지침·코드·설정 이름과 절>
  - 확인 근거:
    - <새로 확인한 반영 사실과 대상 이름·실행 근거>
  - 남은 적용:
    - <남은 범위 | 없음>
  - 재발 방지 효과:
    - <확인 결과와 근거 | 미확인>

## 사건 경과

- 작업·요청: <당시 작업 또는 사용자 요구 핵심 요약>
- 기대 동작·규칙:
  - <기대 결과>
- 실제 결과·영향:
  - <관측 사실과 기대 결과와의 차이>
    - 근거: <로그 시각 | 파일과 절 | 링크>
- 수행 절차:
  1. <실제 수행한 순서>
- 관련 문서:
  - <관련 지침 이름과 절>

## 원인과 처리

- 원인:
  - <확인된 원인 | 미확인>
    - 근거: <확인 위치 | 명령 결과>
- 조치 사항:
  - <실제 조치 사항>
- 미조치 사항:
  - <남은 문제 사항>

## 예방 행동

- <예방 행동 이름>
  - 조건: <문제 발생 조건 문장>
  - 행동: <다음 세션에서 수행할 예방 행동 문장>
  - 준수 기준: <행동의 준수 여부를 확인할 기준 문장>
```
