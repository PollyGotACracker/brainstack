# 작업 상태 규칙

## 목적

- 에이전트 간 프로젝트 맥락을 공유한다.
- 사용자가 작업 사항을 확인한다.
- 추후 작업 재개 시 참조한다.

## 작성 대상

- 저장소 구조 변경·코드 수정·기능 기획은 작업별 공용 상태 문서를 작성한다.
- 구조 변경에 속한 이동은 해당 작업 기록에 포함한다.
- 단순 이동·사건 기록 작성 같은 부수 작업은 개별 기록에서 제외한다.
- 종류가 다른 작업을 동시에 진행하면 파일을 분리한다.
- 같은 종류 작업의 날짜가 다르면 날짜·시각 외 동일한 작업 ID로 파일을 분리한다.

## 작성 승인

- 기록 폴더 문서는 사용자 승인 후 작성·수정한다.
  결과와 함께 변경 위치를 보고한다.

## 상태 값

### 작업 상태

- `미개시`는 실행 승인 전 상태이다.
- `진행`은 구현·검수 중이거나 남은 작업이 있는 상태이다.
- `중단`은 재작업 중단 조건에 따른 사용자 판단 대기 상태이다.
- `완료`는 모든 요구사항의 검수 판정이 PASS인 상태이다.

### 검수 판정

- `PASS`는 기대 결과 충족이 실행·대조 근거로 확인된 상태이다.
- `FAIL`은 기대 결과 미충족이 확인된 상태이다.
- `미측정`은 측정 전이거나 측정 환경이 없는 상태이다.

## 절별 내용

### 경과 관련 절

- `작업 경과`에는 갱신 시각, 진행 상황, 다음 작업과 담당을 적는다.
- `중단 사유`는 작업 상태가 `중단`일 때만 작성한다.
- `작업 기록`에는 의미 있는 작업 경과를 시점별 항목으로 적는다.
  새 항목은 절 맨 위에 추가한다.

### 요구사항 관련 절

- `요구사항 목록`에는 요구사항별 목표·결과·작업·검수·기대 결과를 적는다.
- `확정 결정`에는 사용자 확정 결정과 제약을 항목별 출처와 함께 적는다.
- `문제 정의`에는 관측 문제, 근거, 처리할 요구사항을 적는다.
- `원인 분석`에는 확인된 원인 또는 미확인, 근거, 한계를 적는다.

### 계획 관련 절

- `승인 범위`에는 승인자·연결 대상·승인 행동·영향 범위·승인 상태를 반드시 적는다.
- `변경 범위`에는 기준 커밋·읽기 범위·변경 대상·유지 대상·변경 전 원본·배정 범위를 적는다.
- `기준 자료`에는 자료별 위치와 조사 결과를 적는다.
- `잠재적 위험`에는 위험과 확인 방법을 적는다.

### 검수 관련 절

- `검수 계획`에는 실행 위치, 검증 명령과 대상 요구사항, 실제 검증 조건을 적는다.
- `검수 결과`에는 시점별 요구사항 판정과 근거를 적는다.
- `재작업`에는 위반 위치·기대 결과·재작업 범위·횟수·재검수 결과를 적는다.

### 역할별 입력

- worker·reviewer 입력은 `요구사항 목록`, `확정 결정`, `승인 범위`, `변경 범위`, `기준 자료`, `잠재적 위험`, `검수 계획` 절이다.
  재작업 시 `재작업` 절을 추가한다.
- worker·reviewer 열람 범위는 `읽기 범위`의 행과 기준 커밋 이후 변경분(diff)으로 한정한다.
  범위 밖 확인이 필요하면 경로·범위·사유를 결과에 기재한다.
- 그 외 절은 작업 경과와 결과 보관에 쓴다.

## 표기

### 기록 원칙

- 양식 필드에 해당하는 현재 작업 내용만 기재한다.
- 기록할 내용이 없는 필드에는 `기록 없음`을 표기한다.
- 요구사항 문장은 공용 Core의 `문장 작성` 소절 기준을 따른다.
- 문서 내 에이전트 지칭은 역할로만 작성한다.
- 범위·결정·제약·진행 상태가 바뀌면 해당 항목을 갱신한다.
- 추가 지시를 상위 작업에 합친 경우 합친 사실을 기록한다.
- 상태 문서 갱신 작업 자체는 작업 기록에서 제외한다.
- 구현 결과는 director가 독립 확인한 사실과 결과물 이름만 기재한다.
- worker·reviewer의 대화·중간 설명·추론·도구 출력·결과 보고 원문은 제외한다.
- 사용자 발언은 직접 인용 대신 내용 핵심 요약으로 연결한다.
- 사용하는 시각은 KST로, 아래 커맨드를 사용한다.

```bash
TZ=KST-9 date '+%Y%m%d-%H%M'
```

### 식별자 표기

- 작업 ID는 `YYYYMMDD-HHMM-<영문-slug>` 형식이다.
  날짜·시각은 파일 생성 시각(KST)으로 표기한다.
- 파일명은 `<작업-id>.md`이다.
- 부속 문서는 `<작업-id>-<용도>.md`이며 파일명 접두사로 작업을 연결한다.
- 대상·자료는 이름과 경로를 병기한다.
- 위치는 절 제목·기호로 표기한다.
  읽기 범위 제한용 행 범위와 기준 커밋을 병기한다.
  기준 커밋 이후 변경된 파일은 절 제목·기호로 위치를 재확인한다.

## 작성 절차

### 작성 단계

1. 적용 규칙과 해당 작업의 공용 상태 문서를 확인한다.
2. 해당 작업 파일이 없으면 아래 템플릿을 기반으로 생성한다.
3. 작업 진행에 따라 해당 절을 갱신하고 `작업 경과`의 갱신 시각을 변경한다.
4. 기록 결과를 실제 파일에서 확인하고 변경 위치를 보고한다.

