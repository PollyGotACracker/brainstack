# 작업 흐름

- 단계 순서를 이 Skill 한 곳에 정의한다.

## 의도 파악

- 작업을 시작하기 전, 첫 프롬프트의 의도를 확인한다.
- `사건 확인`, `incident 확인` 요청:
  1. log/incident/ 가장 최신 문서부터 `미적용`, `부분 적용`된 문서 확인
  2. 파일 경로와 현재 상태 제시, 어떤 사건의 워크플로우를 개선할 것인지 질문
- `상태 확인`, `state 확인` 요청:
  1. log/state/ 가장 최신 문서부터 `미개시`, `진행`, `중단`된 문서 확인
  2. 파일 경로와 현재 상태 제시, 어떤 작업을 시작 또는 재개할 것인지 질문
- 세션 확인 요청:
  1. 세션에서 중단된 작업이 있는지 분석
  2. 세션 흐름에서 발견되는 워크플로우 이슈가 있는지 분석
  3. 사용자에게 어떤 문제를 다룰 것인지 질문
- 로그 확인 요청: 로그에서 발견된 이슈 확인 후 사용자에게 질문
- 기타 요청: 프롬프트 확인 후 사용자에게 의도를 직접 질문

## 목적 분류

| 목적      | 대상                        | 파일           |
| --------- | --------------------------- | -------------- |
| 설계      | 구현 전 방안 결정           | `research.md`  |
| 구현      | 승인된 방향의 코드 변경     | `implement.md` |
| 디버깅    | 관찰된 오동작의 원인과 수정 | `debug.md`     |
| 지침·문서 | 지침·Skill·양식·문서 변경   | `document.md`  |

- director가 사전 질문에 목적을 적는다.
- 목적 확정 직후 해당 목적 파일만 읽는다.
- 진행 중 목적이 바뀌면 바뀐 목적의 파일을 읽고 사용자에게 알린다.
- 목적이 섞이면 목적별로 나눠 진행한다.
- 저장소 관련 작업은 Claude Code, Codex를 전부 고려하며, 터미널은 bash를 기본으로 한다.

## 보고 템플릿

- 각 보고 직전에 `templates/` 폴더의 해당 파일을 읽는다.

| 보고           | 파일                           |
| -------------- | ------------------------------ |
| 사전 질문      | `templates/pre-question.md`    |
| 착수 보고      | `templates/kickoff.md`         |
| 조사 결과 보고 | `templates/research-result.md` |
| 계획 승인 요청 | `templates/plan-approval.md`   |
| 중단 보고      | `templates/stop.md`            |
| 완료 보고      | `templates/completion.md`      |
| 제안 검토      | `templates/proposal-review.md` |

## 공통 단계

1. director가 `templates/pre-question.md`로 사전 질문한다.
   사전 질문 전 같은 요구사항의 상태 문서가 있는지 확인한다.
2. director가 `templates/kickoff.md`로 착수 보고하고 승인을 받는다.
   외부 자료가 필요한 작업이면 초안 전 외부 조사를 착수 보고에 적는다.
3. documenter가 승인 근거와 실행 내용을 상태 문서에 승인 기록으로 남긴다.
4. 착수 보고에서 승인된 외부 조사만 planner가 수행한다.
5. director가 프로젝트 코드를 조사해 목적별 초안을 작성한다.
6. planner가 반증을 1회 수행한다.
7. director가 verify Skill로 반증 결과를 대조한 뒤 조사 결과를 보고한다.
   보고에는 `templates/research-result.md`를 쓴다.
   사용자 판단을 받은 뒤 다음 단계로 진행한다.
8. 목적별 후속 단계는 목적 파일을 따른다.
9. director가 `templates/completion.md`로 완료 보고한다.

## 공통 규칙

### 하위 에이전트 호출

- 반증 입력은 반증할 주장, director 확인 범위, 원문 발췌, 판정 기준이다.
- 입력 경계는 로컬 전용 Core의 `하위 에이전트 입력`·`에이전트 간 전달` 절을 따른다.

### 기록

- 승인·결정·최종 상태는 documenter가 상태 문서에 기록한다.
- director는 기록 완료를 확인한 뒤 다음 단계로 진행한다.

### 추가 지시와 중단

- 추가 지시는 상위 작업 범위와 대조해 포함되면 병합한다.
- 재작업 지속 여부는 로컬 전용 Core의 `재작업 중단` 절로 정한다.
- 중단 보고에는 `templates/stop.md`를 쓴다.
- 중단 후 사용자 판단이 끝나면 바뀐 실행 내용을 승인 기록부터 다시 진행한다.

### 사용량 제한

1. 사용량 경고나 제한 오류가 발생하면 새 하위 에이전트 호출을 중단한다.
2. 실행 중인 에이전트 결과와 직접 확인 가능한 자료로 작업을 계속한다.
3. 필수 검수가 불가능하면 미완료로 보고하고 상태 문서에 사유를 기록한다.
