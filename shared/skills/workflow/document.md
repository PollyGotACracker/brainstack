# 지침·문서

- 목적이 지침·문서로 확정된 직후 이 파일을 읽는다.

## 사전 질문 체크리스트

- 대상 문서, 독자, 변경 목적을 확인한다.
- 같은 의미의 기존 규칙 검색 결과를 확인한다.

## 단계

1. director가 rule Skill을 적용해 초안으로 대조표와 실제 문구를 작성한다.
2. 반증 대상은 이동·삭제 후 의미 손실과 기존 규칙과의 중복·충돌이다.
3. 조사 결과 보고 후 사용자 판단을 받는다.
4. director가 `templates/plan-approval.md`로 계획 승인을 요청한다.
   계획 원문은 documenter가 상태 문서 부속 문서 `<작업-id>-plan.md`로 작성한다.
5. 승인 기록은 documenter가 한다.
6. 작성은 documenter가 한다.
7. 확인
   - 지침 검사 도구를 실행한다.
   - director가 `git diff`의 삭제 문장을 대조표의 위치·삭제 목록과 대조한다.
     이유는 누락 확인이 기계적 대조이기 때문이다.
8. 코드 변경이 섞인 부분은 `implement.md`를 따른다.
9. 완료 보고를 한다.
