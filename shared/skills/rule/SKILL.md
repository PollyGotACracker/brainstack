# 지침 설계

## 지침 위치

- 프로젝트 지침에 지침 파일 배치가 정해진 경우 해당 기준을 적용한다.
- 특정 작업의 절차·예시는 해당 Skill 문서에 배치한다.
- 같은 의미는 한 위치에 정의하고 다른 위치에는 참조만 배치한다.
- 새 지침·Skill 생성 전 같은 작업을 다루는 기존 Skill·지침을 검색한다.
  존재하는 경우 해당 문서의 개정·통합을 우선 검토한다.

## 설계 절차

1. 지침 생성·수정 전 지침의 설계 근거 문서를 확인한다.
   - 프로젝트에 지식 저장소가 있는 경우 저장소를 검색해 근거 문서를 탐색한다.
   - 위키 검색 절차가 정해진 경우 해당 절차를 적용한다.
   - 찾은 근거 문서의 원문을 확인하고 관련 항목과 변경 근거를 연결한다.
   - 적용 조건·행동·판정 기준이 겹치는 기존 위치를 확인한다.
   - 기존 확인 결과에는 상위 지침의 결과 재사용 기준을 적용한다.
2. 유지·개정·통합·신설 중 필요한 처리를 결정한다.
   - 사실과 설계 해석을 구분하고 변경 근거와 정의 위치를 연결한다.
3. 적용 조건·수행 행동·확인 가능한 완료 기준을 긍정형으로 작성한다.
   - 제한이 필요한 규칙은 허용 대상·적용 조건·대안 행동으로 작성한다.
   - 지침 문장 작성 또는 다른 역할 전달 전 부정 어미와 문장 길이를 검사한다.
   - 프로젝트 지침에 지침 검사 도구가 정해진 경우 경로·절 제목·절 참조 변경 후 검사한다.
     검사 후 참조한 절의 내용을 대조한다.
   - 검사 항목은 다음과 같다.
     - 경로
     - 절 참조
     - 부정형
4. 대표 적용·비적용 사례와 변경된 요구사항을 연결해 대조한다.
   - 대상·근거·기존 문구·개정 문구·적용 사례와 남은 미확인 사항을 보고한다.
5. 제안 제출 전 1~4단계 수행 여부를 확인한다.

## Skill 작성

### 프론트매터

- `name`은 영문 소문자·숫자·하이픈으로 64자 이하로 작성한다.
- `description`에는 Skill의 기능과 사용 시점을 함께 작성한다.
  사용 시점에는 사용자가 실제로 쓸 요청 표현을 포함한다.
  사용 시점 정보는 본문 대신 `description`에 배치한다.

### 본문과 참조 파일

- 본문은 500줄 이하로 작성한다.
  긴 참조 자료는 같은 Skill 폴더의 별도 파일로 분리한다.
  참조 파일은 `SKILL.md`에서 한 단계로 연결한다.
  참조 파일마다 읽을 시점을 기재한다.

### 스크립트

- 반복되는 결정적 작업은 스크립트로 제공한다.
  스크립트마다 실행용 또는 참조용 여부를 기재한다.

### 공통 규칙

- 같은 대상에는 같은 용어를 사용한다.
- 시점에 따라 바뀌는 정보는 현행 방법과 이전 방법으로 구분해 기재한다.
- 규칙마다 필요한 이유를 병기한다.
- 본문에는 저장소 경로 대신 상위 지침·프로젝트 지침의 기준을 기재한다.

## Skill 검증

- 대표 요청으로 Skill 적용 결과를 확인한다.
- `description` 검증에는 호출 대상 요청과 비대상 요청을 함께 작성한다.
  비대상 요청은 키워드가 겹치지만 다른 작업이 필요한 요청으로 선정한다.
- 확인하지 못한 활성화·준수 여부는 미측정으로 보고한다.
