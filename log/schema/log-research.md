# 설계 문서 기록 규칙

## 목적

- 프로젝트 환경을 고려한 설계 판단 과정과 결정을 보존한다.
- 구현 작업의 사전 질문 출처를 제공한다.

## 작성 대상

- workflow Skill의 설계 목적 작업마다 1개를 작성한다.
- 상태 문서와 별도 파일로 작성한다.

## 작성 승인

- 기록 폴더 문서는 사용자 승인 후 작성·수정한다.

## 상태 값

- `결정`은 사용자가 후보를 선택한 상태이다.
- `보류`는 추가 정보가 필요해 결정을 미룬 상태이다.
- `기각`은 모든 후보를 채택하지 않은 상태이다.

## 표기

- 출처는 `파일:행` 또는 사용자 요구 핵심 요약으로 적는다.
- 짧은 값 비교는 표로, 문장 근거는 목록으로 적는다.
- 기록할 내용이 없는 필드에는 `기록 없음`을 적는다.
- 파일명은 `<설계-id>.md`이다.
- `제약` 절에는 외부 API·실행 환경 같은 사용자 결정 외 제약을 기재한다.
- 사용하는 시각은 KST로, 아래 커맨드를 사용한다.

```bash
TZ=KST-9 date '+%Y%m%d-%H%M'
```

## 템플릿

```markdown
# 설계 문서: <검토 이름>

- 설계 ID: <설계-id>
- 관련 작업 ID: <작업-id | 없음>
- 결정 상태: <결정 | 보류 | 기각>
- 결정 일시: <YYYY-MM-DD HH:MM>

## 검토 대상

- 목표: <1문장>
- 배경: <사용자 요구 핵심 요약>

## 프로젝트 환경

- <항목>: <값> (출처: <`파일:행`>)

## 제약

- <제약> (출처: <`파일:행` | 사용자 요구 핵심 요약>)

## 판단 기준

- <기준>: <통과 조건>

## 후보 비교

| 후보   | <기준1> | <기준2> |
| ------ | ------- | ------- |
| <후보> | <값>    | <값>    |

- <후보>: <근거와 출처>

## 반증 결과

| 주장   | 판정  |
| ------ | ----- | ---- | ------- |
| <주장> | <지지 | 반증 | 미확인> |

- <주장>: <근거와 출처>

## 결정

- 선택: <후보 | 보류·기각 사유>
- 근거: <사용자 판단 요약>

## 미확인

- <항목>: <사유>

## 구현 인계

- 요구사항 초안: <항목>
- 완료 기준 초안: <항목>
- 관련 작업: <작업-id | 기록 없음>
```
